# 0.1.0 开发候选迁移指南

本指南面向从早期原型迁移到当前开发候选的部署。先在副本和非生产环境执行；当前候选尚未获得生产发布批准。

## 1. 备份和盘点

备份配置、`data/`、`codeCache/`、插件包、证书和密钥引用，记录 bundle、设备、协议实例、监听地址和外部依赖。不要把密钥值写入配置、日志或迁移记录。

## 2. 配置迁移

以新安装包的 `pdr-runtime.properties` 为基线逐项合并，不要用旧文件整体覆盖。

- 生产环境启用管理认证；同一身份的 `tokenEnvironment` 与 `tokenFile` 只能选一种，推荐文件密钥以支持原子轮换。
- 将共享全权限 token 迁移为 `pdr.management.authentication.principals.<N>.*`，只授予所需权限。
- 对管理写请求启用 request ID，并为幂等、任务、审计和隔离状态配置持久化路径。
- 审核 webhook、OTLP、MQTT 和 ROS 的 CA、客户端证书、私钥及主机名校验；生产环境不得跳过验证。
- 多设备改用 `pdr.<family>.count` 和 `pdr.<family>.<N>.*`。明确每个实例的 `required`；必需实例离线会令 readiness 返回 503。
- 外部协议也使用索引实例，并明确超时、重连退避、消息和资源边界。

合并后执行配置 Schema 和安全门禁，修正未知键、类型、范围及生产策略错误后再启动。

## 3. 插件迁移

先预检 manifest、Runtime API/ABI、依赖、发布者签名和信任策略，不要直接复制未知原生库到在线 bundle 目录。高风险插件应迁到隔离宿主，并通过 apply/list/remove 生命周期管理。quarantine 只能阻止重复启动，不能隔离进程内原生崩溃。

## 4. 客户端迁移

管理客户端应为每个写请求发送唯一 request ID，并处理异步任务状态。客户端还需处理认证失败、权限不足、冲突重放、任务排队、降级 readiness 和结构化故障响应。Web 登录复用管理身份时配置 `pdr.auth.management`；本地无认证模式不可进入生产。

## 5. 部署和回滚演练

在停机窗口执行升级预检和事务应用。启动后核对进程唯一性、`/health/live`、`/health/ready`、`/health/detail`、设备和协议诊断、Web 页面、审计记录与持久化恢复，并演练一次回滚和中断恢复。包验证应使用独立端口和数据目录，不替换正在运行的 9080 实例。

若启用 Bundle 仓库发布者授权，旧 attestation schema v1 不能直接进入防回放模式。先冻结当前在线
仓库，用 schema v2、一个受控初始 `rolloutSequence`、干净发布清单和绑定的 SPDX SBOM 重新签署，启动新 Runtime 并确认
`repository-rollout-high-water.properties`、`last-known-good.properties` 和无前缀精确 LKG 一致；
之后每个候选必须使用更高序号。同序号不得由并行流水线签署不同摘要。`committing` 中断只能恢复
提交，不能回退；低于高水位的旧签名包会在 OSP 初始化前拒绝。

若已经生成早期 schema v1 高水位，不要删除它。用相同仓库摘要和序号补齐发布清单/SBOM 来源后
启动一次；提交会把高水位与 LKG 元数据原位升级为 schema v2。来源证据、摘要或序号任一不一致都
必须作为新候选使用更高序号，不能覆盖旧高水位。

## 6. 放行证据

最终源码冻结后重新运行完整 Release CTest，生成资格报告，并签署 PetaLinux、真实协议、生产身份、现场网络和 24/72 小时长稳证据。把资格报告、测试日志、产物清单及外部报告生成签名证据包，在独立环境离线校验。`LOCAL_VALIDATION_PASSED` 不等于生产批准。

## 7. 停止条件

出现配置或契约失败、产物哈希不一致、签名/信任失败、必需设备持续离线、readiness 降级原因不明、审计或持久化不可写、回滚/恢复失败、资格报告为 `DENIED` 或强制外部证据缺失时，停止迁移并回滚。
